# ASPIRE — findings ledger

Single source of truth. Append only; never rewrite history.
Nothing is fixed that is not in this table first.

Status ∈ `open` / `fixed` / `wontfix (reason)` / `needs-decision` / `deferred` /
`decided` / `measured, not changed`.

The last three were added in P12, because "fixed" was doing work it should not:

* **decided** — a `needs-decision` row where the decision *is* the deliverable.
  The tradeoff is written into the code at the point it applies, dated, with the
  rejected alternative and why. P1-010 and P9-005.
* **deferred** — out of scope by an owner instruction, not by judgement. Says
  who and when so it can be picked up rather than forgotten.
* **measured, not changed** — the finding's own proposed fix was conditional on
  a number nobody had. The number is now collected; the change waits for it.
  P8-003, and it is deliberately not called fixed.

Every audited row is terminal. One NEW finding was surfaced by the work and is
open: **P12-001** -- the response cache sits on `POST /chat`, and the client
has used `POST /chat/stream` since P0-001 was adopted. So the caching work in
P7-003, P7-004 and P7-006 is correct and currently unreached in production.
It is left open deliberately: fixing it changes the primary transport and
deserves its own commit and tests rather than a hurried one at the end of a
batch.

Three more things are worth reading before treating this as "done":

1. **P9-001, P9-002, P7-002 are deferred, not solved.** CSP, HSTS, the `:80`
   redirect and the co-tenanted Valkey instance are all still exactly as the
   audit found them. They were excluded by instruction on 2026-08-04 because
   they live in `deploy/`; the findings themselves stand.
2. **P10-002 (no i18n system) remains wontfix.** The ES/FR interface is still
   entirely English. P10-005 and P10-006 fixed the *mechanics* around it — the
   document language tag and locale-aware formatting — which makes the eventual
   i18n work smaller, and makes the gap more visible rather than less.
3. **P5-001's long-task breach did not reproduce** on the machine used for the
   P12 measurements. The DOM and heap half (P5-003) did, and is fixed and
   measured; the commit-count claim is inferred from rendering 8 rows instead of
   502, not observed.
